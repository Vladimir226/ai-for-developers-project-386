# Рабочий процесс тикетов

Правила выведены ретроспективой 2026-11-07 (после #2, #12, #3) и обязательны
на каждом тикете: от занятия issue до её закрытия.

## Старт тикета

1. Занять: `gh issue edit <n> --add-assignee @me`.
2. Проверить окружение до первой строки кода: `docker version` (colima),
   `gh auth status`, зелёный CI на main. Отсутствие инструмента — вопрос
   пользователю здесь же, а не на этапе приёмки.
3. Ветка `t<n>-slug` от свежего main; один тикет — один PR (squash-мерж).
4. Прочитать до дизайна: ТЗ + аддендумы issue, связные ADR
   (`docs/adr/` — канонические файлы; исторический контекст —
   `bmad-output/architecture.md`), TypeSpec-контракт (`contract/`) для
   API-тикетов — формы ответов берутся из контракта, не изобретаются.

## Реализация

- TDD: падающий тест → реализация → рефакторинг.
- Проба перед дизайном: допущение о фреймворке или СУБД (поведение бандлера,
  пул соединений, резолвинг путей) проверяется минимальным экспериментом до
  основного кода. Цена пробы — минуты, цена ошибки в допущении — циклы сборки.
- Пиннинг-тест: дизайн, стоящий на допущении, фиксирует допущение тестом
  (пример: единственное соединение Prisma — `src/lib/db/connection.test.ts`).
- Буква спеки расходится с семантикой примитива (per-connection pragma и
  т.п.) → реализация по семантике, компромисс зафиксирован в PR-описании и
  комментарии issue.
- Проверяемые команды (CI-гейты, drift-check, тесты) идут без пайпа, exit-код
  читается отдельно: пайп маскирует падение.
- После правки shell-скриптов и точечных правок — перечитать затронутый файл
  целиком (указатель на shebang, stray-правки).

## Ревью и мерж

- Каждый PR проходит двухосевое ревью (Standards + Spec, скилл `code-review`,
  два параллельных саб-агента). Находки — в комментарий PR: исправленное и
  принятое осознанно.
- Режим авто-мержа: зелёный CI = мерж без вопроса. Исключение — тикеты с
  гейтом пользователя: #13 (утверждение мудбордов и HTML-прототипа).
- Закрытие: итоговый комментарий по критериям приёмки + `gh issue close`
  (если не закрылся от `Closes #n` в PR).
