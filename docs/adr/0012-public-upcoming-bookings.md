# Публичный список предстоящих броней без auth

**Status:** Accepted
**Drives:** страница «Предстоящие записи» (`/bookings`)
**Date:** 2026-11-08

**Context:** Прототип дизайн-этапа (#13, `events.html`) показывает «Предстоящие
события» — список подтверждённых броней. Auth в системе нет и не будет
(ADR-0003), сущности «гость» в схеме БД нет, поэтому «свои» брони гостя
неотличимы от чужих. Сервис к этому моменту задеплоен публично (#41).

**Decision:** Страница «Предстоящие записи» (`/bookings`) публично показывает
**все** предстоящие брони **всех** гостей, read-only, с полными полями
(тип, интервал, имя, контакт, комментарий, время создания) — паритет с
прототипом и `/admin`. Данные берутся существующим
`GET /api/v1/bookings?upcoming=true` через SDK, без изменений контракта.
Редактирование и отмена — только у владельца в `/admin` (#36).

**Consequences:**

- Экспозиция данных гостей (имя, контакт, комментарий) на публичном URL не
  увеличивается относительно уже открытого `/admin` (accepted cost ADR-0003),
  но становится заметнее. Пересмотр доступа к админ-поверхностям — отдельный
  тикет.
- Проект учебный, данные демо: уровень риска принят владельцем осознанно.

**Alternatives:** localStorage-привязка id броней к браузеру (честные «мои
записи», но список теряется при смене устройства/чистке данных); поиск по
контакту (перебор контактов раскрывает чужие брони); магические ссылки
(идентифицируют одну бронь, а не список). Отклонены как auth-суррогаты с
худшими компромиссами для MVP.

**Revisit when:** появятся реальные (не демо) данные гостей — тогда
localStorage-привязка или токены вместо публичного списка.
